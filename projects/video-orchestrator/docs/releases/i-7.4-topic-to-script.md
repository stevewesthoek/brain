## Overview

I-7.4 implements deterministic script generation from ranked topics with mandatory approval gates. The system:

- **Selects topics** from ranked backlogs without human intervention
- **Generates deterministic scripts** using channel-specific templates (not AI)
- **Enforces approval gates** blocking automation until human review completes
- **Requires theological review** for Says the Bible (theological accuracy enforcement)
- **Keeps all scripts private** until explicitly approved and published
- **Exposes scripts via Brain Core API** for Brain Console visibility
- **Prevents automation bypass** — approval status must be checked before downstream triggers

## Key Design Decisions

### 1. Deterministic Templates (Not AI)

Scripts are generated using **rules-based templates**, not AI models:

- **Says the Bible:** Narrative structure with Scripture-focus requirements
- **ProChat:** Pain → Insight → Solution framework for B2B SaaS founders

Templates are **skeleton structures** with placeholder sections (`[MAIN_CLAIM]`, `[ACTION_1]`, etc.) for human editing. This ensures:
- Deterministic output (same input → same structure)
- Clear approval boundaries (human fills in the blanks)
- No AI drift or variability in generated content

### 2. Approval Gate (BLOCKING)

Approval status is stored in `metadata.approval`:

```json
{
  "approval": {
    "required": true,
    "status": "pending | approved | rejected",
    "theologicalReviewRequired": true,  // Says the Bible only
    "approvedAt": "ISO8601 or null",
    "approvedBy": "reviewer name or null",
    "notes": "approval notes"
  }
}
```

**Blocking behavior:**
- Scripts are created with `status: "draft"` and `approval.status: "pending"`
- Downstream automation (generation, publishing) **must check approval status**
- Rejected scripts have `approval.notes` explaining why
- No automation proceeds until `approval.status === "approved"`

### 3. Theological Review Enforcement

For Says the Bible only: `theologicalReviewRequired: true`

This enforces:
- Two-phase approval (script review + theological review)
- Cannot bypass to automation until both complete
- Brain Core API exposes the status for Brain Console
- Separate reviewer roles (content editor + theologian)

### 4. Privacy (All Content Remains Private)

- Scripts are created as `status: "draft"` with no public visibility
- Brain Core API reads from private job directories
- Brain Console (Obsidian) shows drafts only to authenticated user
- No public listing or exposure of unapproved content
- YouTube upload only proceeds after approval

## Implementation Files

### A. Script Contract (Metadata Schema)

**File:** `jobs/{jobId}/metadata/script.json`

Schema structure:
```typescript
{
  jobId: string;              // Unique job identifier
  channelId: string;          // 'says-the-bible' | 'prochat'
  topicId: string;            // Topic from backlog
  status: 'draft' | 'ready' | 'generating' | 'generated' | 'published';
  title: string;              // Topic title
  targetDurationSeconds: number; // From content profile
  wordCount: number;          // Estimated/actual word count
  scriptKey: string;          // Path to script markdown
  generatedBy: string;        // 'manual-template-v1'
  createdAt: string;          // ISO 8601 timestamp
  updatedAt: string;          // ISO 8601 timestamp
  approval: {
    required: boolean;        // Always true
    status: 'pending' | 'approved' | 'rejected';
    theologicalReviewRequired: boolean;
    approvedAt: string | null;
    approvedBy: string | null;
    notes: string | null;
  };
}
```

**Location:** `projects/video-orchestrator/cloud/jobs/*/metadata/script.json`

**Committed:** ✅ (generated by select-topic-for-script.sh)

### B. Topic Selection Script

**File:** `projects/video-orchestrator/cloud/scripts/select-topic-for-script.sh`

**Usage:**
```bash
./select-topic-for-script.sh <channelId> <topicId> <jobId>

# Example:
./select-topic-for-script.sh says-the-bible stb-baptism-001 stb-script-001
./select-topic-for-script.sh prochat prochat-ai-code-001 prochat-script-001
```

**What it does:**
1. Validates topic exists in channel backlog
2. Validates content profile exists
3. Creates `jobs/{jobId}/metadata/` and `jobs/{jobId}/scripts/` directories
4. Generates `topic.json` (selected topic metadata)
5. Generates deterministic `script.md` (template skeleton for channel)
6. Generates `script.json` with approval gate (`status: "pending"`)

**Deterministic template selection:**
- `says-the-bible` → Narrative: Scripture focus, reverent tone, theological accuracy
- `prochat` → Pain → Insight → Solution framework, B2B SaaS founder focus

**Output:**
```
Files created:
  Topic metadata:  jobs/{jobId}/metadata/topic.json
  Script markdown: jobs/{jobId}/scripts/script.md
  Script metadata: jobs/{jobId}/metadata/script.json

Status: draft (approval pending)
Word count: [skeleton estimate]
Theological review required: [true|false]
```

**Committed:** ✅

- **CTA (55–60s):** Specific call-to-action with accountability loop

Requirements:
- Actionable in 1 week
- Founder language (SaaS terminology)
- Real pain point
- Clear CTA with feedback loop

Review checklist:

## Safety & Constraints

### Privacy Enforcement

- ✓ All scripts created as `status: "draft"`
- ✓ No public listing or exposure
- ✓ Brain Core API returns approval status for gating
- ✓ Brain Console (Obsidian) shows drafts only to authenticated user
- ✓ No YouTube upload until approval AND downstream automation checks

### Approval Gate (CRITICAL)

- ✓ `approval.status` stored in metadata
- ✓ Downstream automation must check before proceeding
- ✓ No bypass mechanism (no flag to skip approval)
- ✓ Rejection stored with notes for human review
- ✓ Says the Bible requires theological review (two-phase)

### Deterministic Generation

- ✓ Templates are rules-based, not AI
- ✓ Same topic + channel → same template structure
- ✓ No variability from model inference
- ✓ Safe for batch operations (reproducible)

### No Automation Bypass

- ✓ Script selection does NOT trigger generation
- ✓ Script selection does NOT trigger publishing
- ✓ Script selection does NOT trigger YouTube upload
- ✓ Approval gates block ALL downstream automation
- ✓ Human review is required + explicit approval

3. Show "Awaiting Approval" badge

### Downstream: Video Generation (Phase 5+)

Video generation will:
1. Read script metadata
2. **Check:** `if (script.approval.status !== 'approved') { throw }` 
3. **Prevent:** Generation if approval is pending/rejected
4. **Log:** Approval checker result for audit trail

### Downstream: YouTube Publishing (Phase 6+)

YouTube publishing will:
1. Read script + video metadata
2. **Verify:** `allowPublicPublishing === false` (privacy enforced)
3. **Check:** Approval status before upload
4. **Prevent:** Public upload if not approved
