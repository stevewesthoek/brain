# ProChat Script Template

## Channel Profile
- **Duration:** 60 seconds
- **Format:** Narrative, B2B SaaS founder-focused
- **Framework:** Pain → Insight → Solution → CTA
- **Tone:** Direct, conversational-expert, practical
- **Key Requirement:** CTA required (drives action)
- **Privacy:** All scripts private until explicitly published

---

## Structure (Timings)

### Hook (0–5s)
Grab attention with the problem founders face.

**Pattern:**
```
Here's what I see:

[TOPIC_TITLE]

[Pause]

This is killing SaaS teams. Let me break it down.
```

**Guidelines:**
- Urgent but not alarmist
- Speak from experience
- Use direct, active language
- Imply: "I've seen this pattern"

### Pain (5–20s)
Describe the specific pain point in founder terms.

**Pattern:**
```
Most founders [PAIN_POINT]:

- They [SYMPTOM_1]
- They [SYMPTOM_2]
- Result: [CONSEQUENCE]
```

**Requirements:**
- Recognize real, felt pain
- Use founder language ("burn rate," "churn," "unit economics")
- Be specific enough to resonate
- Show business impact (not just technical)

### Insight (20–40s)
Why the problem exists + what most miss.

**Pattern:**
```
But here's what most miss: [INSIGHT]

The real issue is: [ROOT_CAUSE]

[DATA_POINT or OBSERVATION]: [SUPPORTING_EVIDENCE]

This changes the game because [WHY_IT_MATTERS].
```

**Requirements:**
- Provide a reframe (shift perspective)
- Cite data/observation if possible
- Connect to founder's bottom line
- Move from "what's wrong" to "why it matters"

### Solution (40–55s)
What to do (actionable, founder-executable).

**Pattern:**
```
Here's what works:

1. [ACTION_1]: [HOW_IT_FIXES_PAIN]
2. [ACTION_2]: [WHAT_CHANGES]

Result: [OUTCOME]
```

**Requirements:**
- Two concrete actions (not vague principles)
- Founder can start this week
- Show the payoff
- Practical and tactical

### Call to Action (55–60s)
Drive specific behavior (not passive consumption).

**Pattern:**
```
If your team is facing this, try [ACTION_1] next week.

Tag me when you ship it. I want to see it work.
```

**Tone:** Conversational, accountability-focused, personal

**Requirements:**
- Specific, time-bound action
- Creates feedback loop
- Personal/direct (not "subscribe")

---

## Word Count & Formatting

- **Target:** 150–200 words
- **Script format:** Plain Markdown
- **Data/metrics:** Include numbers if available (e.g., "70% of early-stage teams...")
- **Founder language:** Use SaaS/startup terminology naturally

---

## Approval Gate

**Before publishing, script MUST:**

- [ ] CTA is specific and actionable
- [ ] Pain point is real for founders
- [ ] Insight provides genuine reframe
- [ ] Solution is implementable in 1 week
- [ ] Tone is conversational (not preachy)
- [ ] Data/claims are accurate
- [ ] Founder would actually do the action

**Theological Review:** NOT required  
**Approval Required:** YES  
**Blocking:** ✓ YES — automation paused until approved

## Examples

### Example 1: Build Auth First

```markdown
# Build Auth First

## Hook
Here's what I see:

Most SaaS teams build auth last.

This is killing your launch timeline. Let me break it down.

## Pain
Most founders:

- Build features first, then realize they need user management
- Retrofit auth into existing code (expensive rewrite)
- Delay launch waiting for custom auth solution
- Result: 6 weeks turned into 16 weeks

## Insight
But here's what most miss: Auth is infrastructure, not a feature.

The real issue is treating auth like a sprint task instead of a Day 1 foundation.

Stripe took 6 months off their launch timeline by baking auth into their API from the start.

This changes the game because every feature after auth is 10x faster when users are properly authenticated.

## Solution
Here's what works:

1. Use Clerk or Auth0 Day 1: It's not cheating—it's smart. Get user management for free.
2. Design your data model around auth primitives: Organizations, roles, permissions first.

Result: Shipping in 8 weeks instead of 16. Real monetization earlier.

## Call to Action
If your team is facing this, set up Clerk in your next sprint.

Tag me when you ship it. I want to see it work.
```

## B2B SaaS Safety Guardrails

These are red flags during review. Do not approve if:

1. **Vague pain** — "Founders struggle" but doesn't specify the problem
2. **No reframe** — Just venting without insight
3. **Unactionable solution** — "Work harder" or "Think bigger" (too abstract)
4. **Unrealistic timeline** — "Do this in 2 hours" (when it takes days)
5. **Missing CTA** — "Subscribe for more tips" (no action driver)
6. **Wrong audience** — Advice for scale-stage companies posted to pre-seed founders
7. **False data** — Citing stats without source
