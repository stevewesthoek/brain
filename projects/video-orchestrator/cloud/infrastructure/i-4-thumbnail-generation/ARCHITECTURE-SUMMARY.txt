================================================================================
I-4 THUMBNAIL EXTRACTION: ARCHITECTURE DECISION SUMMARY
================================================================================

THREE ARCHITECTURES EVALUATED:

┌─ OPTION 1: MediaConvert Native Frame Capture ✅ RECOMMENDED
│
├─ How: Add FrameCaptureSettings output group to existing MediaConvert job
├─ Cost: $0.01-0.02 per thumbnail (minimal overhead)
├─ Setup time: 1-2 hours (Phase 1 validation)
├─ Operational burden: Minimal (no new services)
├─ Reliability: Highest (native AWS, 99.99% SLA)
├─ Deployment prerequisites: None (ready to test NOW)
├─ Maintenance: Minimal
├─ Tradeoff: Captures at 1-sec intervals (acceptable for thumbnail)
│
└─ Timeline to MVP: 2.5-3 hours
   ├─ Phase 1 (30 min): Validate frame capture works
   ├─ Phase 2 (1-2 hr): Integrate with Lambda
   └─ Phase 3 (1 hr): Update Step Functions + test

────────────────────────────────────────────────────────────────────────────────

┌─ OPTION 2: Lambda + ffmpeg Layer (FALLBACK READY)
│
├─ How: Lambda calls ffmpeg subprocess to extract frame
├─ Cost: $0.00001 per invocation (cheaper, but requires layer setup)
├─ Setup time: 3-4 hours (includes 1-2 hr for layer build)
├─ Operational burden: Medium (layer versioning, binary updates)
├─ Reliability: High (ffmpeg + Lambda both proven)
├─ Deployment prerequisites: Build static ffmpeg (1-2 hours)
├─ Maintenance: Quarterly (layer updates)
├─ Benefit: Arbitrary timestamp support (e.g., 3.5 seconds exactly)
│
├─ Why NOT recommended for MVP:
│  ├─ Requires ffmpeg layer build (1-2 hour upfront cost)
│  ├─ More moving parts (Lambda + layer + IAM + binary)
│  └─ MediaConvert option equally reliable, simpler
│
└─ When to use: If timestamp precision becomes requirement, or at scale 1000+/mo

   Fallback path documented: Code ready, just need layer

────────────────────────────────────────────────────────────────────────────────

┌─ OPTION 3: ECS/Fargate Worker (NOT RECOMMENDED)
│
├─ How: Deploy container with ffmpeg, trigger via Lambda
├─ Cost: $0.05-0.10 per job + $10-30/month idle cost
├─ Setup time: 5-8 hours (Docker, ECR, ECS, IAM)
├─ Operational burden: High (container patching, image mgmt)
├─ Reliability: Medium (more failure points)
├─ Deployment prerequisites: Docker, ECR, ECS knowledge
├─ Maintenance: Continuous (container base image updates)
│
└─ Only justified at extreme scale or for complex processing
   (Not appropriate for MVP with 1-2 jobs/day)
