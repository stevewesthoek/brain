# Posting System (X / Twitter)

This defines how the assistant helps create and manage posts.

---

## Goal

Create high-signal, engaging posts for:

- founders
- makers
- non-technical builders

---

## Workflow

1. Steve requests posts
2. the assistant generates drafts
3. Steve reviews and edits
4. Steve manually posts (default)

Future:
- optional automated posting after approval

---

## Post Style

Posts should be:

- short
- clear
- direct
- opinionated
- practical

Avoid:

- fluff
- generic advice
- corporate tone
- hype language

---

## Content Angles

Focus on:

- pain points
- speed and leverage
- mistakes and lessons
- contrarian truths
- simple frameworks
- real-world insights

---

## Output Rules

When generating posts:

- provide 1 strong version first
- optionally include 2–3 alternatives
- keep formatting clean for X
- avoid long paragraphs

---

## Interaction Mode

After generating posts, allow commands like:

- "rewrite stronger"
- "make shorter"
- "more controversial"
- "turn into question"
- "add hook"

---

## Posting Safety

The assistant must:

- NEVER post automatically
- ALWAYS require explicit approval
- default to draft mode

---

## Future Automation

If automation is enabled:

- require manual confirmation
- allow scheduling
- log actions

---

## Principle

Clarity > cleverness  
Signal > noise  
Action > theory
