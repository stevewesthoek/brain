# Infinite Brain rollout template v1

Use one lifecycle for every consumer/domain activation: `CONFORMANT → CANARY_READY → CANARY_ACTIVE → CANARY_ACCEPTED → DEFAULT_ACTIVE`, with `DEGRADED`, `ROLLED_BACK`, and `BLOCKED` exits. Each rollout records the universal contract version, descriptor and route revisions, capability handshake, atomic context metrics, Task/Evidence packets, composition graph, proportional quality/safety gates, fallback, rollback receipt, and observed outcome.

Consumer rollout changes only adapter mechanics and capability translation. Domain rollout changes only bounded qualification evidence. Neither creates a new router, catalog, gate system, context architecture, or semantic policy fork. Cross-cutting services remain shared services; Bible authority remains under Research, Review/QA remain gates, Careful remains safety, Handoff remains continuity, and Memory remains bounded context.

Legacy paths remain until stable volume, accepted quality, a rollback-tested window, stable context, universal conformance, and no material incidents justify retirement. Monitoring is receipt-based and stores no raw prompt, transcript, secret, or full context dump.
