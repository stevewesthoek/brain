> **Source review is not runtime provenance.** Reviewing the committed source confirms
> the code is admissible. It does not confirm that the file that will actually execute
> matches that reviewed source.
>
> **Admission is NOT client registration.** `candidate` means Brain has reviewed and
> approved the committed source for local use pending runtime-entrypoint provenance.
> It does not mean the server is running or any client has connected to it.
> As of 2026-08-02, no `[mcp_servers.workbench]` entry exists in `~/.codex/config.toml`
> and no `mcpServers.workbench` entry exists in `~/.claude.json`.

Workbench is an external provider and consumer-facing execution host. Its MCP
server, authentication, action projection, source policy, grants, operation and
dispatch stores, n8n execution, reconciliation, rollback, audit, and receipts
remain in Workbench. Brain does not copy or fork those implementations.

Brain admits only three MCP tools for the B1.0a vertical slice:

- `getWorkbenchStatus` (read-only)
- `readWorkbenchContext` (read-only)
- `runWorkbenchCommand`, limited to `n8n_workflow_migration` (external mutation, two-phase approval)

The provider enforces that scope from environment values generated by Brain.
The credential value remains in an owner-only file outside both repositories.
Project registrations (`.codex/config.toml`, `.claude.json`, etc.) are generated
runtime configuration, not authority.

## Manual Setup by IDE

### Claude Code
1. Read: `claude-code-config.template.json`
2. Replace placeholders:
   - `<absolute-path-to-workbench-private>` → your repo path

### Antigravity (macOS)
1. Read: `mcp-http-config.template.json` OR use stdio approach below
2. Symlink setup (if using HTTP relay):
   ```bash
   mkdir -p "$HOME/Library/Application Support/Antigravity/User"
   ln -sfn \
     "$(pwd)/operations/system-configs/antigravity/User/mcp.json" \
     "$HOME/Library/Application Support/Antigravity/User/mcp.json"
   ```
3. Edit `operations/system-configs/antigravity/User/mcp.json` (ignored by git):
   ```json
   {
     "mcpServers": {
       "workbench": {
         "type": "http",
         "url": "http://localhost:3053",
         "auth": {
           "type": "bearer",
           "token": "<workbench-credential-token>"
         }
       }
     }
   }
   ```
4. Restart Antigravity

## Environment Variables

The Workbench MCP server requires these environment variables at startup:

| Variable | Purpose | Default / Example |
|----------|---------|----------|
| `WORKBENCH_MCP_CREDENTIAL_FILE` | Path to credential file with auth token | `/Users/you/.credentials/workbench-mcp.token` |
| `WORKBENCH_MCP_ALLOWED_TOOLS` | Comma-separated tools to admit | `getWorkbenchStatus,readWorkbenchContext,runWorkbenchCommand` |
| `WORKBENCH_MCP_ALLOWED_COMMAND_KINDS` | Comma-separated command kinds | `n8n_workflow_migration` |

## Credential File Setup

The credential file must be **ignored by git** and stored outside both repositories.

### Create the credential file
```bash
# Choose location (e.g., ~/.credentials/ or ~/.config/)
mkdir -p ~/.credentials
echo "<your-workbench-mcp-token>" > ~/.credentials/workbench-mcp.token
chmod 600 ~/.credentials/workbench-mcp.token
```

### Verify it's ignored
```bash
git check-ignore -v ~/.credentials/workbench-mcp.token
# Should return: path is ignored
```

### Reference in config files
Use the absolute path in each IDE config:
```json
{
  "env": {
    "WORKBENCH_MCP_CREDENTIAL_FILE": "/Users/yourname/.credentials/workbench-mcp.token"
  }
}
```

### Verify exact scope
Once connected, verify the server exposes exactly the admitted tools:
- `getWorkbenchStatus` ✓
- `readWorkbenchContext` ✓
- `runWorkbenchCommand` ✓ (only with `n8n_workflow_migration` suboperation)

A successful read-only `getWorkbenchStatus` call proves connectivity and
authentication only. It does not authorize B1.0a prepare, execute, fixtures,
deployment, rollback, or any other mutation.

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| "MCP server not found" | Config not merged or syntax error | Check config file, restart IDE |
| "Cannot find module" or "Command not found" | Node not in PATH or path incorrect | Use absolute path to node, test with `node --version` |
| "Authentication failed" | Credential file not found or invalid | Verify path, check file permissions (600), verify token |
| "Address already in use" | Another process on port 3053 (if relay) | Kill existing relay or MCP server process |
| Server appears in one IDE, not others | Inconsistent config paths | Use templates from this directory, verify all paths match |
| No tools listed | Scope environment variables not set | Check `WORKBENCH_MCP_ALLOWED_*` variables are passed |
| Timeout on first call | Server startup slow or stalled | Increase startup timeout in IDE, check server logs |

## Security Rules

1. **Never commit credentials** — Store tokens only in ignored files outside repositories
2. **Always use absolute paths** — Templates contain placeholders; replace with full paths
3. **Enforce exact scope** — Only admitted tools (getWorkbenchStatus, readWorkbenchContext, runWorkbenchCommand.n8n_workflow_migration) should be available
4. **Verify artifacts** — Run admission validator before each test to catch digest drift
5. **Never bypass the provider** — Always use the Workbench MCP server for authorized actions; no direct HTTP fallback
6. **Ambiguous mutations require reconciliation** — Never retry mutation calls after transport failure; require durable operation receipts

## Revocation

If you need to disable Workbench MCP:

1. Set the admission status to `paused` or `revoked` in `operations/specs/mcp-provider-admissions.json`
2. Remove or disable the generated registration from each IDE config file
3. Delete the credential file reference (keep the credential file for recovery)
4. Preserve the provider source, admission history, and validation output
5. Do not delete provider code or historical evidence

Do NOT delete the admission entry — retain it for audit and potential recovery.
