## Cutover contract

The isolated drill composes `brain-control-plane-cutover-v1` metadata with the
existing `brain-control-plane-relocation-v1`, D0-C package verifier, D0-D
install verifier, and D0-E logical snapshot/import contract. The deterministic
cutover sequence is: closed fixture source, read-only relocation-final export,
snapshot verification, same-revision darwin package verification and install,
fresh target StateStore import, evidence-backed readiness, foreground target
Core/Console startup, semantic HTTP smoke, clean shutdown, and target restart.
The source remains closed/inactive throughout. No service manager is invoked.

Readiness no longer trusts caller booleans. It inspects the actual verified
snapshot/mode, source path and read-only availability, target package and
install receipts, current target schema/record hashes, target portable config,
external fixture secret references, and bounded target authority state. The
legacy boolean-only `createRelocationPlan` compatibility shape is deliberately
always blocked. Linux is contract-tested through the same package/install
metadata; no live Linux acceptance is claimed.

## Authority and recovery

Host-local authority is classified without direct SQL mutation: bounded runs,
effects, leases/fences, uncertainty, active runs, and existing recovery
classification are inspected. Imported source PIDs are never signalled. Lease
and fence evidence is not reset or reused as fresh authority; future safe work
must use normal `markControllerLost`/`reAdmitRun` semantics and a fresh higher
fence. Uncertain or awaiting-receipt effects remain non-replayable and require
operator/reconciliation handling. Completed work, schedules, Jarvis state, K5
state, reviews, attention, budgets, exact-once IDs, and control receipts are
not rerun or regenerated by target startup. There is no automatic source
failback; reverse relocation after target writes requires a new quiesced
snapshot.
