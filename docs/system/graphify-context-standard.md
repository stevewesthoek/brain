# Graphify Context Standard

**Status:** frozen legacy projection pending B8.5 bounded semantic migration
**Last updated:** 2026-08-11
**Scope:** Brain repo, Brain-derived repos, terminal LLMs, IDE assistants, agent runners, and CLI workflows

## Purpose

Graphify is a non-authoritative generated projection. It is no longer Brain's structural-navigation default: accepted Codebase Memory MCP owns structural architecture/symbol/route/caller-callee/blast-radius navigation when fresh, and exact current source remains authoritative. Graphify stays frozen until B8.5 accepts its bounded semantic-synthesis role.

Brain is modular, standardized, and normalized: memory, work queues, ledgers, docs, adapters, and UIs are separate upgradeable modules with stable contracts. Graphify belongs in that same layer as a repo-context index. It gives fast navigation to files, symbols, communities, and architectural neighborhoods without forcing every tool to re-read the repository.

## Standard Rule

For structural repo context, follow B8.4 rather than Graphify-first behavior.

```text
Structural architecture/symbol/route/caller/blast-radius question
  -> use fresh Codebase Memory MCP navigation when available
  -> identify likely files/symbols/relationships
  -> read exact current source
  -> patch or claim authority only after exact source verification

CBM stale/unavailable/unknown
  -> bounded exact-source search/read

Known file or known symbol
  -> direct exact-source read
```

Existing Graphify artifacts may still narrow context as generated projections, but they do not replace CBM structural navigation and cannot serve as authority.

## Canonical Artifacts

Every graphified repo should expose:

```text
graphify-out/GRAPH_REPORT.md   human-readable overview
graphify-out/graph.json        machine-readable graph
graphify-out/graph.html        interactive human navigation
graphify-out/manifest.json     extraction/update manifest
```

These artifacts are read-only context inputs for LLMs. They are generated by the phased Graphify scheduler and should not be hand-edited.

## Consumer Contract

Any terminal LLM, IDE assistant, model selector consumer, or agent runner working inside a repo should follow this contract:

1. Use fresh Codebase Memory MCP for structural navigation before broad exploration when the question is architectural/symbolic/relational.
2. Use exact current source as authority before edits, policy/security decisions, runtime/provider claims, or final factual claims.
3. If CBM is stale, unavailable, or freshness is unknown, use ordinary bounded repository search/read instead.
4. Treat Graphify and other generated projections as stale-prone navigation hints only.
5. Never patch code/docs, authorize writes, or override canonical roadmaps/status from graph/projection evidence alone.

## Upgrade Boundary

Graphify remains separately upgradeable. Consumers depend only on the artifact contract above, not on Graphify internals or one assistant-specific behavior.

The production generation path is centralized in:

```text
tools/scripts/office-nightly-scheduler.sh
  -> tools/scripts/graphify-nightly.sh
```

The scheduler runs the numeric phased model documented in `operations/runbooks/graphify-nightly.md`.
