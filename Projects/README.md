# Projects Context

This folder contains project-specific context for Steve’s active and historical products.

## Purpose

Use this folder to understand:

- what each project is
- why it exists
- target audience
- current scope
- positioning
- implementation notes
- project-specific decisions and constraints

## How to Use This Folder

Treat each project subfolder as a self-contained context area.

When Steve asks about a specific product, project, repo, idea, or SaaS concept:

1. identify the relevant project folder
2. read the most central markdown files in that folder
3. prefer project-specific instructions over generic assumptions
4. keep global business context from the root brain repo in mind

## Priority Rules

Default priority order:

1. PROBOT.md
2. root-level canonical files
3. Projects/README.md
4. relevant project folder markdown files
5. supporting notes inside that project folder

If a project file conflicts with global operating rules:
- follow global safety and behavior rules
- but prefer project-specific product context for that project itself

## What Counts as Project Context

Examples:

- product overview
- scope
- target audience
- pricing ideas
- implementation notes
- product strategy
- launch notes
- feature decisions
- repo links
- prompts
- internal documentation

## What NOT to Assume

Do not assume every project is:

- active
- launch-ready
- approved for development
- safe to modify automatically

Project context is for understanding first, not execution by default.

## Execution Rules for Projects

For project-related work:

- default to read-only analysis
- summarize before changing
- prefer suggestions, plans, and drafts unless Steve explicitly asks for modifications
- obey RESTRICTED_REPOS.md at all times

## Notes

Some project folders may be incomplete, outdated, or exploratory.
If context is sparse:

- say what is missing
- make the best grounded assumption
- continue with a practical answer
